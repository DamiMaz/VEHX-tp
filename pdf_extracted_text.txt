DOCUMENTO DE ESPECIFICACIÓN DE PRODUCTO & ARQUITECTURA (PRD)
Sistema de Gestión Vehicular, Matrices de
Combustible y Telemetría de Movimiento
Requerimientos funcionales, modelo de datos, algoritmos de consumo, mantenimiento preventivo y diseño
de APIs externas
Este documento establece las bases técnicas y funcionales para el desarrollo de una aplicación móvil
enfocada en la administración integral de automóviles. El sistema resuelve dos problemáticas críticas de
los conductores: la trazabilidad financiera y operativa del consumo de nafta mediante matrices
comparativas mensuales, y la gestión predictiva de mantenimientos mecánicos (services) combinando
registros de carga con estimación de kilometraje diario mediante APIs de movimiento y telemetría.
01. Requerimientos Funcionales Core
1. Gestión de Garaje Multi-Vehículo
Permite registrar uno o múltiples rodados con su
ficha técnica base: marca, modelo, año,
motorización (Nafta, Diésel, GNC, Híbrido),
capacidad del tanque, tipo de transmisión y
kilometraje inicial de partida.
2. Registro de Cargas y Odómetro
Captura ágil en estación de servicio de odómetro
actual, litros surtidos, costo monetario e indicador
de tanque lleno. Calcula el tramo recorrido desde
la carga inmediata anterior y el rendimiento real.
3. Matrices Mensuales de Consumo
Agrupación automática de cargas por mes
calendario y año. Consolida distancia recorrida,
volumen de combustible, erogación total, costo por
kilómetro y variaciones porcentuales
intermensuales.
4. Motor Predictivo de Services
Planificador con lógica bimodal (por kilometraje
acumulado o tiempo calendario). Se alimenta tanto
de las cargas de nafta como del rastreo pasivo de
movimiento por APIs para emitir alertas
preventivas.
02. Requerimientos No Funcionales y de Operación
Estándares de Arquitectura Móvil, Usabilidad y Consumo de Batería
Arquitectura Offline-First: En estaciones de servicio o cocheras subterráneas la conectividad
suele ser nula. La aplicación debe persistir registros en una base de datos local (SQLite) y
sincronizar en segundo plano al recuperar red.
Experiencia de Carga en 15 Segundos (UX): Interfaz de alto contraste operable con una sola
mano, teclado numérico directo al abrir el formulario y autocompletado del precio por litro según
la última carga o geolocalización.
Eficiencia Energética en Sensores: El rastreo de movimiento diario no debe utilizar GPS
continuo en alta precisión; debe apoyarse en APIs nativas de reconocimiento de actividad
vehicular de bajo consumo energético.

04. Algoritmo de Consumo y Cargas Parciales
El cálculo de rendimiento exige conocer exactamente cuántos litros reemplazaron el volumen consumido.
El sistema aplica la siguiente formulación matemática entre la carga anterior (i−1) y la actual (i):
Distancia_Tramo (Δkm) = Odómetro[i] − Odómetro[i−1]
Rendimiento_Real (km/L) = (Odómetro[i] − Odómetro[último_lleno]) / ∑
Litros[parciales + actual]
Costo_Por_Kilómetro ($/km) = Gasto_Total_Acumulado / Distancia_Tramo
Resolución Técnica del Problema de "Carga Parcial"
Si el usuario carga $15.000 (ej. 12 litros) sin llenar el tanque, es físicamente imposible saber cuánta
nafta gastó en los kilómetros previos porque el nivel final del tanque es incierto. Regla de negocio:
Cuando el usuario desmarca "¿Tanque lleno?", el sistema registra los litros y el importe para la
matriz contable del mes, pero marca el rendimiento como "Acumulando...". En la siguiente ocasión
en que el usuario llene el tanque al 100%, el motor suma todos los litros parciales intermedios y los
divide por la diferencia de odómetro respecto al último tanque lleno validado.

06. Motor de Reglas para Services (Desgaste Bimodal)
Las piezas y fluidos de un automóvil sufren degradación tanto por fricción mecánica (kilómetros) como
por oxidación química y envejecimiento de polímeros (tiempo). El sistema evalúa una condición lógica
OR donde el alerta salta ante el primer umbral que llegue al 90% de su vida útil:
ACEITE Y FILTROS
10.000 km
ó 12 meses (Sintético/Semi)
KIT DE DISTRIBUCIÓN
60.000 km
ó 48 meses (Correa dentada)
LÍQUIDO FRENOS / BUJÍAS
40.000 km
ó 24 meses (Higroscopía)
Cálculo del Índice de Desgaste y Predicción de Fecha de Service
Para cada componente k, el sistema calcula el porcentaje de desgaste actual como el máximo
entre la fracción de kilómetros recorridos y la fracción de días transcurridos desde el último service:
Desgaste(k) = MÁX [ (Odómetro_Estimado − Km_Último_Service) /
Intervalo_Km , (Fecha_Hoy − Fecha_Último_Service) / Intervalo_Días ]
Si el usuario pasa 3 semanas sin cargar combustible (por ejemplo, en tanques grandes o vehículos
diésel), depender únicamente del odómetro manual atrasaría las alertas. Aquí interviene el módulo
de APIs de control de movimiento para actualizar el Odómetro Estimado todos los días en
segundo plano.

de APIs externas y sensores del sistema operativo móvil:

A. Control de Movimiento y Ritmo Diario (Dead Reckoning + Calibración)
¿Cómo saber que el usuario viaja en SU auto y no en taxi, colectivo o en otro vehículo?
Google Activity Recognition API / Apple CMMotionActivityManager: Detectan mediante
acelerómetro y giroscopio cuando el teléfono pasa a estado IN_VEHICLE sin activar el chip
GPS permanentemente.
Filtro por MAC Bluetooth / Android Auto / CarPlay: Para evitar sumar kilómetros cuando el
usuario viaja en transporte público, el conteo automático se activa únicamente si el teléfono
detecta simultáneamente el estado IN_VEHICLE y la conexión al Bluetooth del estéreo del auto
registrado.
Mapbox Map Matching / Google Roads API: Durante el trayecto toma muestras espaciadas de
ubicación (cada 60–120 segundos via FusedLocationProvider) y las ajusta a la traza vial real,
calculando los kilómetros diarios recorridos.
Fórmula de Odómetro Virtual Autocalibrado
El kilometraje estimado hoy es: Odómetro_Virtual(t) = Odómetro_Última_Nafta + ∑ (Km_API_Diarios ×
Factor_Corrección_α). Cuando el usuario carga nafta e ingresa el odómetro real del tablero, el sistema
compara su estimación con la realidad, corrige el valor exacto y ajusta el coeficiente α para mayor precisión
futura.

09. Ampliaciones del Producto y Hoja de Ruta (Roadmap)
Fase 1: MVP (Meses 1 a 2)
Alta de vehículos, carga manual rápida de nafta
(con lógica de tanque lleno/parcial), generación de
la matriz mensual comparativa, alertas base de
services y persistencia Offline-First.
Fase 2: Movimiento y OCR (Meses 3 a 4)
Integración de Activity Recognition API + vínculo
Bluetooth para estimar el ritmo diario de kilómetros
en segundo plano. Escaneo de tickets de
combustible mediante cámara e IA.
Fase 3: Gestión Documental y Anomalías
Alertas por vencimiento de VTV/ITV, póliza de
seguro, oblea de GNC, matafuegos y patentes.
Detector estadístico de fallas si el rendimiento cae
más de un 15% respecto al histórico.
Fase 4: Pasaporte Vehicular y Flotas B2B
Exportación de "Certificado de Historial de
Mantenimiento" en PDF para aumentar el valor de
reventa del usado. Panel web para pequeñas flotas
de remises, utilitarios o logística.
Stack Tecnológico Recomendado para el Inicio del Proyecto
Frontend Multiplataforma: Flutter o React Native (con módulos nativos para Background Location
y Bluetooth). Base de Datos Local: SQLite (mediante Drift o WatermelonDB) para operación sin
señal. Backend y Sincronización: Supabase (PostgreSQL + Auth + Edge Functions) para
resguardar copias de seguridad en la nube y ejecutar los cálculos programados de alertas push
(Firebase Cloud Messaging).
